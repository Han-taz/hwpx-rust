# Contributing

## Local Checks

Run these before opening a pull request:

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace
cargo bench -p hwp-core --bench parse_benchmark -- --test
cargo check --manifest-path fuzz/Cargo.toml --locked
cargo deny --locked check
cargo audit
cargo audit --file fuzz/Cargo.lock
python3 packages/hwpx-python/scripts/check_release_versions.py
python3 packages/hwpx-python/scripts/check_release_versions_test.py
python3 packages/hwpx-python/scripts/check_pyo3_gil_release.py
python3 -m py_compile \
  packages/hwpx-python/scripts/check_release_versions.py \
  packages/hwpx-python/scripts/check_release_versions_test.py \
  packages/hwpx-python/scripts/check_pyo3_gil_release.py \
  packages/hwpx-python/scripts/check_wheel_contents.py
```

For Python packaging changes, also build and inspect a wheel:

```bash
uv tool run maturin build \
  --release \
  --locked \
  --compatibility pypi \
  --interpreter python3 \
  --out dist \
  -m packages/hwpx-python/Cargo.toml

python3 packages/hwpx-python/scripts/check_wheel_contents.py dist/*.whl
```

## Fixtures and Snapshots

- Put small public test documents in `crates/hwp-core/tests/fixtures/`.
- Do not add private or sensitive documents.
- If a JSON/HTML/Markdown snapshot changes intentionally, inspect the `.snap.new`
  file before accepting it with `cargo insta accept --workspace`.

## Parser Diagnostics

Unsupported or lossy parsing should be represented with structured diagnostics rather
than silently ignored.

## Performance Work

Benchmark usage is documented in [docs/performance.md](docs/performance.md). CI
compiles the Criterion benchmark in test mode to catch benchmark/API drift without
using noisy shared-runner timing as a release gate. Pull requests that claim a speedup
should include local benchmark evidence and the tested fixture, platform, and Rust
version.

## Coverage

Coverage usage is documented in [docs/coverage.md](docs/coverage.md). CI uploads an
LCOV artifact generated by `cargo-llvm-cov`. For parser, diagnostics, conversion, or
Python binding changes, review the coverage artifact or include local coverage notes
when the change adds significant untested paths.

## Fuzzing

Fuzzing usage is documented in [docs/fuzzing.md](docs/fuzzing.md). CI builds fuzz
targets on nightly to catch stale parser harnesses, while long-running fuzz campaigns
are run manually or in dedicated security automation.

## Security Expectations

- Treat HWP/HWPX files as hostile input.
- Keep HWPX ZIP, XML, and section resource limits intact unless the security model is
  updated with a clear reason.
- Do not use document-provided paths for filesystem writes.
- Do not add dependencies that bypass `deny.toml` policy.
- Document new parser recovery behavior with diagnostics and tests.

See [docs/security-model.md](docs/security-model.md) for the current threat model and
resource limits.

## Release Checklist

Release steps are documented in [docs/release.md](docs/release.md). Keep Python package
versions, Rust workspace versions, `Cargo.lock`, `hwpx.__version__`, and release tags
synchronized.
